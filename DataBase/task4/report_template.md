### Символы и нотация

Все символы, которые понадобятся в задачах. Можно копировать отсюда.

| Символ | Название                              | Что означает                                                |
| ------ | ------------------------------------- | ----------------------------------------------------------- |
| `→`    | функциональная зависимость            | `X → Y` — «X определяет Y»                                  |
| `→→`   | многозначная зависимость (MVD)        | `A →→ B` — «одному A соответствует множество B»             |
| `*`    | зависимость проекции/соединения (PID) | `*(R₁, …, Rₙ)` — «R восстанавливается соединением проекций» |
| `⁺`    | замыкание атрибутов                   | `Z⁺` — множество всех атрибутов, выводимых из Z             |
| `π`    | проекция                              | `π_{A,B}(R)` — оставить только столбцы A, B                 |
| `⨝`    | естественное соединение               | соединяет две таблицы по общим атрибутам                    |
| `\`    | разность множеств                     | `R \ B` — все атрибуты R, кроме атрибутов B                 |
| `⊆`    | подмножество (нестрогое)              | `A ⊆ B` — «A входит в B, возможно совпадая»                 |
| `⊄`    | не подмножество                       | `A ⊄ B` — «A не входит в B целиком»                         |
| `∩`    | пересечение множеств                  |                                                             |
| `∪`    | объединение множеств                  |                                                             |
| `∈`    | принадлежит множеству                 | `A ∈ Z` — «A входит в Z»                                    |
| `⟺`    | эквивалентность                       | «тогда и только тогда»                                      |
| `∧`    | логическое И                          | «и то, и другое»                                            |
| `∨`    | логическое ИЛИ                        | «хотя бы одно из двух»                                      |
| `¬`    | логическое НЕ                         | «неверно, что»                                              |
| `≠`    | не равно                              |                                                             |

## Задача 1. БИБЛИОТЕКА (2НФ)

1.  FD:  
    ЧИТ_БИЛЕТ → ИМЯ_ЧИТАТЕЛЯ  
    КНИГА_ШИФР → НАЗВАНИЕ  
    КНИГА_ШИФР → АВТОР  
    {ЧИТ_БИЛЕТ, КНИГА_ШИФР, ДАТА_ВЫДАЧИ} → ДАТА_ВОЗВРАТА
2.  Возможные ключи:  
    {ЧИТ_БИЛЕТ, КНИГА_ШИФР, ДАТА_ВЫДАЧИ} 
    Ни один из его атрибутов кдюча нельзя вывести из остальных зависимостей, поэтому при удалении любого атрибута набор уже не определяет полную запись о выдаче.

3.  Нормальная форма:  
    При атомарных значениях схема находится в 1НФ, но не во 2НФ: ЧИТ_БИЛЕТ → ИМЯ_ЧИТАТЕЛЯ и КНИГА_ШИФР → НАЗВАНИЕ, АВТОР — частичные зависимости неключевых атрибутов от частей составного ключа. Зависимость даты возврата от полного ключа не нарушением 2НФ.

4.  Декомпозиция до 3НФ:  
    ЧИТАТЕЛИ(ЧИТ_БИЛЕТ, ИМЯ_ЧИТАТЕЛЯ)  
    КНИГИ(КНИГА_ШИФР, НАЗВАНИЕ, АВТОР)  
    ВЫДАЧИ(ЧИТ_БИЛЕТ, КНИГА_ШИФР, ДАТА_ВЫДАЧИ, ДАТА_ВОЗВРАТА)

5.  Проверка без потерь:  
    Сначала отделяем ЧИТАТЕЛИ от остальных атрибутов. Общий атрибут ЧИТ_БИЛЕТ определяет всю таблицу ЧИТАТЕЛИ. Затем выделяем КНИГИ; общий атрибут КНИГА_ШИФР определяет НАЗВАНИЕ и АВТОР. Оба разложения без потерь по теореме Хита, поэтому исходные данные восстанавливаются соединением по общим атрибутам.

Ответ на вопрос: почему ответ не зависит от длины ключа?

> Зависимость неключевого атрибута от собственного подмножества составного ключа является частичной, а частичная зависимость нарушает 2НФ. Правило не зависит от того, сколько атрибутов входит в ключ: важно, зависит ли атрибут от всего ключа или только от его части. У ключа из одного атрибута собственных непустых частей нет, поэтому частичной зависимости от него быть не может.

## Задача 2. ЗАКАЗЫ (2НФ + 3НФ)

1.  FD:  
    НОМ_ЗАКАЗА → ДАТА  
    НОМ_ЗАКАЗА → КЛИЕНТ  
    КЛИЕНТ → ГОРОД_КЛИЕНТА  
    КЛИЕНТ → СКИДКА_КЛИЕНТА  
    ТОВАР → ЦЕНА_ТОВАРА  
    {НОМ_ЗАКАЗА, ТОВАР} → КОЛ_ВО

2.  Возможные ключи:  
    {НОМ_ЗАКАЗА, ТОВАР}. Замыкание этой пары содержит все атрибуты схемы: номер заказа определяет дату и клиента, клиент — город и скидку, товар — цену, а пара заказа и товара — количество. Это минимальный ключ: НОМ_ЗАКАЗА и ТОВАР не определяются другими атрибутами, поэтому удалить любой из них нельзя.

3.  Нормальная форма:  
    При атомарных значениях схема находится в 1НФ, но не во 2НФ: НОМ_ЗАКАЗА → ДАТА, КЛИЕНТ и ТОВАР → ЦЕНА_ТОВАРА — частичные зависимости неключевых атрибутов от частей составного ключа. После их устранения остаётся транзитивная зависимость НОМ_ЗАКАЗА → КЛИЕНТ → ГОРОД_КЛИЕНТА, СКИДКА_КЛИЕНТА, поэтому для исходной схемы требуется также устранение нарушения 3НФ.

4.  Декомпозиция до 3НФ:  
    До 2НФ:  
    ЗАКАЗЫ_ВРЕМЕННО(НОМ_ЗАКАЗА, ДАТА, КЛИЕНТ, ГОРОД_КЛИЕНТА, СКИДКА_КЛИЕНТА)  
    ТОВАРЫ(ТОВАР, ЦЕНА_ТОВАРА)  
    ПОЗИЦИИ_ЗАКАЗА(НОМ_ЗАКАЗА, ТОВАР, КОЛ_ВО)  

    До 3НФ:  
    ЗАКАЗЫ(НОМ_ЗАКАЗА, ДАТА, КЛИЕНТ)  
    КЛИЕНТЫ(КЛИЕНТ, ГОРОД_КЛИЕНТА, СКИДКА_КЛИЕНТА)  
    ТОВАРЫ(ТОВАР, ЦЕНА_ТОВАРА)  
    ПОЗИЦИИ_ЗАКАЗА(НОМ_ЗАКАЗА, ТОВАР, КОЛ_ВО)

5.  Проверка без потерь:  
    На первом шаге ЗАКАЗЫ_ВРЕМЕННО и ПОЗИЦИИ_ЗАКАЗА пересекаются по НОМ_ЗАКАЗА, который определяет все атрибуты ЗАКАЗЫ_ВРЕМЕННО; ТОВАРЫ и ПОЗИЦИИ_ЗАКАЗА пересекаются по ТОВАР, который определяет все атрибуты ТОВАРЫ. На втором шаге ЗАКАЗЫ и КЛИЕНТЫ пересекаются по КЛИЕНТ, который определяет всю таблицу КЛИЕНТЫ. По теореме Хита эти разложения без потерь.

Ответ на вопрос: почему после первого шага схема окажется в 2НФ, но ещё не в 3НФ?

> После первого шага атрибуты, зависящие только от номера заказа или только от товара, вынесены из отношения с составным ключом, поэтому частичных зависимостей больше нет и схема удовлетворяет 2НФ. Но в таблице заказов клиент всё ещё определяет свой город и скидку, то есть остаётся транзитивная зависимость от ключа заказа; её устраняют отдельным отношением КЛИЕНТЫ.

## Задача 3. РАСПИСАНИЕ (перекрывающиеся ключи, НФБК)

1.  FD:  
    ПРЕПОДАВАТЕЛЬ → ПРЕДМЕТ  
    {АУДИТОРИЯ, ВРЕМЯ} → ПРЕПОДАВАТЕЛЬ  
    {ПРЕДМЕТ, ВРЕМЯ} → ПРЕПОДАВАТЕЛЬ  
    {ПРЕДМЕТ, ВРЕМЯ} → АУДИТОРИЯ  
    Из первых и последних зависимостей следует также {ПРЕПОДАВАТЕЛЬ, ВРЕМЯ} → АУДИТОРИЯ.

2.  Возможные ключи:  
    {АУДИТОРИЯ, ВРЕМЯ}, {ПРЕДМЕТ, ВРЕМЯ}, {ПРЕПОДАВАТЕЛЬ, ВРЕМЯ}.  
    {АУДИТОРИЯ, ВРЕМЯ} определяет преподавателя, а тот — предмет. {ПРЕДМЕТ, ВРЕМЯ} определяет преподавателя и аудиторию. {ПРЕПОДАВАТЕЛЬ, ВРЕМЯ} определяет предмет через ПРЕПОДАВАТЕЛЬ → ПРЕДМЕТ, затем по предмету и времени — аудиторию. Все ключи минимальны: ни один атрибут из каждой пары не определяется оставшимся атрибутом.

3.  Нормальная форма:  
    Схема находится в 3НФ, но не в НФБК. Все атрибуты являются ключевыми, поскольку каждый входит хотя бы в один возможный ключ; поэтому зависимость ПРЕПОДАВАТЕЛЬ → ПРЕДМЕТ не нарушает 3НФ. Однако ПРЕПОДАВАТЕЛЬ не является суперключом, поэтому эта FD нарушает НФБК.

4.  Декомпозиция до НФБК:  
    Разлагаем по нарушающей НФБК зависимости ПРЕПОДАВАТЕЛЬ → ПРЕДМЕТ:  
    ПРЕПОДАВАТЕЛИ(ПРЕПОДАВАТЕЛЬ, ПРЕДМЕТ)  
    ЗАНЯТИЯ(ПРЕПОДАВАТЕЛЬ, АУДИТОРИЯ, ВРЕМЯ)  
    В ПРЕПОДАВАТЕЛИ детерминант ПРЕПОДАВАТЕЛЬ — ключ. В ЗАНЯТИЯ ключами являются {ПРЕПОДАВАТЕЛЬ, ВРЕМЯ} и {АУДИТОРИЯ, ВРЕМЯ}; обе таблицы находятся в НФБК.

5.  Сохранение FD:  
    Сохраняются ПРЕПОДАВАТЕЛЬ → ПРЕДМЕТ, {АУДИТОРИЯ, ВРЕМЯ} → ПРЕПОДАВАТЕЛЬ и выведенная из исходных правил зависимость {ПРЕПОДАВАТЕЛЬ, ВРЕМЯ} → АУДИТОРИЯ. Зависимость {ПРЕДМЕТ, ВРЕМЯ} → ПРЕПОДАВАТЕЛЬ (а вместе с ней и {ПРЕДМЕТ, ВРЕМЯ} → АУДИТОРИЯ) не сохраняется: её нельзя проверить только по одной из полученных таблиц.

Ответ на вопрос: что теряется при декомпозиции до НФБК и почему остаются в 3НФ?

> При разложении до НФБК может потеряться сохранение некоторых функциональных зависимостей: их уже нельзя проверить в одной таблице без соединения. В этой задаче теряется локальная проверяемость правила «предмет и время определяют преподавателя». Поэтому ставляют схему в 3НФ: она сохраняет зависимости, и ограничения проще проверять.

## Задача 4. СЕМИНАРЫ (MVD, 4НФ)

1.  MVD и FD:  
    ПРЕПОДАВАТЕЛЬ →→ КУРС  
    ПРЕПОДАВАТЕЛЬ →→ УЧЕБНИК  
    Нетривиальных FD из условий не следует.

2.  Нормальная форма:  
    При атомарных значениях отношение находится в 1НФ. Но отношение не находится в 4НФ: ПРЕПОДАВАТЕЛЬ не является суперключом, а зависимости ПРЕПОДАВАТЕЛЬ →→ КУРС и ПРЕПОДАВАТЕЛЬ →→ УЧЕБНИК нетривиальны.

3.  Декомпозиция до 4НФ:  
    ПРЕПОДАВАТЕЛЬ_КУРС(ПРЕПОДАВАТЕЛЬ, КУРС)  
    ПРЕПОДАВАТЕЛЬ_УЧЕБНИК(ПРЕПОДАВАТЕЛЬ, УЧЕБНИК)  
    В каждом отношении только два атрибута, и заданные правила не создают в них нетривиальных MVD с несуперключевым детерминантом. Разложение без потерь по MVD: исходное отношение восстанавливается естественным соединением этих проекций по ПРЕПОДАВАТЕЛЮ.

Ответ на вопрос: как понять, что в данных действительно есть MVD?

> MVD есть, если для одного преподавателя набор курсов и набор учебников независимы. Это должно следовать из правил предметной области и выполняться для всех допустимых данных, а не быть случайным совпадением в нескольких строках.

## Задача 5. ПОСТАВКИ (PID, 5НФ)

1.  PID:  
    *(ПОСТАВЩИК_ДЕТАЛЬ, ПОСТАВЩИК_ПРОЕКТ, ДЕТАЛЬ_ПРОЕКТ), где  
    ПОСТАВЩИК_ДЕТАЛЬ(ПОСТАВЩИК, ДЕТАЛЬ),  
    ПОСТАВЩИК_ПРОЕКТ(ПОСТАВЩИК, ПРОЕКТ),  
    ДЕТАЛЬ_ПРОЕКТ(ДЕТАЛЬ, ПРОЕКТ).  
    Тройка (ПОСТАВЩИК, ДЕТАЛЬ, ПРОЕКТ) входит в ПОСТАВКИ тогда и только тогда, когда все три соответствующие пары входят в эти проекции. Иными словами, ПОСТАВКИ = ПОСТАВЩИК_ДЕТАЛЬ `⨝` ПОСТАВЩИК_ПРОЕКТ `⨝` ДЕТАЛЬ_ПРОЕКТ.

2.  Нормальная форма:  
    По заданным правилам нет нетривиальных FD и независимых нетривиальных MVD, поэтому отношение удовлетворяет 4НФ. Не находится в 5НФ: действует нетривиальная трёхсторонняя зависимость соединения, которая не сводится к ключевой зависимости. Предполагается, что иных ограничений предметной области нет.

3.  Декомпозиция до 5НФ:  
    ПОСТАВЩИК_ДЕТАЛЬ(ПОСТАВЩИК, ДЕТАЛЬ)  
    ПОСТАВЩИК_ПРОЕКТ(ПОСТАВЩИК, ПРОЕКТ)  
    ДЕТАЛЬ_ПРОЕКТ(ДЕТАЛЬ, ПРОЕКТ)  
    По заданной PID декомпозиция без потерь: естественное соединение трёх проекций восстанавливает ровно исходное отношение.

Ответ на вопрос: в чём принципиальная разница между 4НФ и 5НФ?

> 4НФ устраняет избыточность, возникающую из-за независимых многозначных зависимостей. 5НФ рассматривает более общий случай: нетривиальные зависимости соединения, в том числе трёхсторонние, которые нельзя объяснить одной MVD или ключом. Здесь правило связывает сразу три пары, а не утверждает независимость двух наборов значений при фиксированном поставщике.
