# Семинар 3. Реляционное исчисление

## Цель

Освоить два формализма : исчисление кортежей и исчисление доменов.

Вы научитесь записывать один и тот же запрос двумя способами и убедитесь, что они дают один результат. Это ядро того, что стоит за SQL.

Интерпретатора исчисления не существует . Формулы пишутся в отчёте, проверяются логически и перекрёстно. SQL мы не используем вообще.

## Шаг 1. Подготовка базы данных

Если у вас уже есть `employees.db` с семинара 2 — пропустите этот шаг.

Если базы нет (удалили, потеряли) — выполните:

```bash
cd setup
python init_db.py
cd ..
```

Скрипт создаёт `employees.db` со всеми таблицами и данными.

Посмотреть данные (только для просмотра, не для решения) можно через `sqlite3`:

```bash
sqlite3 employees.db
.tables
.headers on
.mode column
SELECT * FROM employees LIMIT 5;
.quit
```

## Шаг 2. Схема базы

| Таблица     | Атрибуты                          |
| ----------- | --------------------------------- |
| departments | `dept_id`, `dept_name`, `manager` |
| employees   | `id`, `name`, `salary`, `dept_id` |
| projects    | `proj_id`, `proj_name`, `manager` |
| works       | `emp_id`, `proj_id`               |

Связи:

- `employees.dept_id → departments.dept_id` — сотрудник работает в отделе
- `works.emp_id → employees.id`, `works.proj_id → projects.proj_id` — сотрудник работает над проектом

## Шаг 3. Как записывать формулы

### Исчисление кортежей

```
{ <целевой список> | <условие> }
```

- `С ∈ employees` — переменная `С` пробегает по строкам таблицы
- `С.salary` — значение атрибута у текущей строки
- Кванторы: `∃` (существует), `∀` (для всех)
- Логические связки: `∧`, `∨`, `¬`, `→`

Если в условии есть переменная, которой нет в целевом списке, она должна быть связана квантором (`∃` или `∀`).

### Исчисление доменов

```
{ <целевой список> | <условие членства> }
```

- Переменные пробегают не по строкам, а по значениям отдельных атрибутов
- Условие членства: `employees(name : И, salary : З)` — «существует строка, у которой `name = И` и `salary = З`»
- Одна переменная — одно значение

### Пример: одна и та же задача двумя способами

Задача: имена сотрудников с зарплатой > 100 000.

Кортежи:

```
{ С.name | С ∈ employees ∧ С.salary > 100000 }
```

Домены:

```
{ И | employees(name : И, salary : З) ∧ З > 100000 }
```

Обратите внимание:

- В кортежах — одна переменная `С`, целая строка.
- В доменах — две переменные `И` и `З`, по значению на каждый нужный атрибут.
- Результат — один и тот же.

## Шаг 4. Как проверить себя

Интерпретатора нет, но есть четыре надёжных способа самопроверки.

1.  Перекрёстная проверка двух форм.
    Если формула в кортежах и формула в доменах дают один и тот же результат — скорее всего, обе верны. Если расходятся — где-то ошибка.

2.  Проверка на конкретных данных.
    Откройте `sqlite3`, посмотрите на таблицы. Возьмите 1–2 строки, мысленно подставьте в свою формулу. Что она вернёт для этих строк? Совпадает с ожиданием?

3.  Словесная переформулировка.
    Перепишите условие своими словами. Затем перепишите свою формулу своими словами. Формулировки должны совпасть.

4.  Проверка граничных случаев.
    Есть ли строки, которые могли бы случайно попасть в результат, но не должны? Или наоборот?
