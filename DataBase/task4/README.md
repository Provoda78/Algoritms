# Семинар 4. Функциональные зависимости и нормализация

## Цель

Освоить сквозной сценарий проектировщика : по словесному описанию предметной области сформулировать функциональные зависимости, найти ключи, определить нормальную форму и выполнить декомпозицию без потерь.

Каждая задача — это отдельная учебная схема со своими правилами. Вы проходите один и тот же путь от начала до конца: от бизнес-правил до набора таблиц в 3НФ (а иногда — 4НФ или 5НФ).

Интерпретатора FD не существует. Все выкладки пишутся в отчёте и проверяются логически.

Регламент: 80 минут на 5 обязательных задач + 1 задача со звёздочкой на остаток времени. Каждая задача — примерно 12–15 минут.

## Шаг 1. Нотация

### Функциональная зависимость (FD)

X → Y

«Если два кортежа совпадают по X, они совпадают и по Y».

- X — детерминант
- Y — зависимый атрибут
- Тривиальная — `Y ⊆ X`
- Нетривиальная — `Y ⊄ X`
- Минимальная — из детерминанта нельзя убрать ни один атрибут

### Замыкание атрибутов Z⁺ над S

Множество всех атрибутов, которые функционально определяются набором Z.

Алгоритм:

1. `Z⁰ = Z`
2. Повторять проход по всем FD `A → B`: если `A ⊆ Z`, добавить `B` в `Z`
3. Остановиться, когда новых атрибутов больше нет

Ключ: Z — суперключ ⟺ `Z⁺ = весь заголовок`.
Z — возможный ключ, если Z — суперключ и никакое собственное подмножество Z суперключом не является.

### Минимальное покрытие

Множество FD, в котором:

1. Правая часть каждой FD — простой атрибут
2. Детерминант минимален
3. Ни одну FD нельзя убрать, не изменив замыкание

### Декомпозиция без потерь. Теорема Хита

Если `R(A, B, C)` и `A → B`, то
R = π*{A,B}(R) ⨝ π*{A,C}(R)

Разбиение на проекции `{A, B}` и `{A, C}` без потерь .

### Нормальные формы

| Форма | Условие                                                       |
| ----- | ------------------------------------------------------------- |
| 1НФ   | Все атрибуты атомарны                                         |
| 2НФ   | 1НФ + нет частичных зависимостей от ключа                     |
| 3НФ   | 2НФ + нет транзитивных зависимостей (неключевой → неключевой) |
| НФБК  | Каждый детерминант — суперключ                                |
| 4НФ   | НФБК + нет нетривиальных MVD                                  |
| 5НФ   | 4НФ + нет нетривиальных PID, не следующих из ключей           |

MVD: `A →→ B` — «одному A соответствует множество B, независимо от остальных атрибутов».
PID: `*(R₁, R₂, …, Rₙ)` — «R восстанавливается соединением этих проекций».

## Шаг 2. Как проверить себя

1.  Перекрёстная проверка ключа. Если Z — суперключ, постройте `Z⁺` двумя способами: через алгоритм и через вывод по аксиомам. Должно совпасть.
2.  Проверка минимальности FD. Уберите FD из минимального покрытия и посмотрите: изменилось ли замыкание? Если нет — FD была лишней.
3.  Проверка нормальной формы. Для каждой FD `X → Y` в схеме спросите: X — суперключ? X — ключевой атрибут? X — неключевой? Это автоматически классифицирует, какая НФ нарушена.
4.  Проверка декомпозиции. Соедините проекции обратно по общему атрибуту. Должны получить исходное отношение. Если строк стало больше — декомпозиция с потерями.

## Шаг 3. Задачи

Для каждой задачи нужно дать:

1.  Все FD , выведенные из правил предметной области.
2.  Все возможные ключи с обоснованием минимальности.
3.  Определение нормальной формы с указанием, какая именно FD её нарушает.
4.  Декомпозицию до указанной в задаче формы.
5.  Проверку без потерь (теорема Хита или контрпример).
6.  Ответ на вопрос на понимание — своими словами, 1–3 предложения.

### Символы и нотация

Все символы, которые понадобятся в задачах. Можно копировать отсюда.

| Символ | Название                              | Что означает                                                |
| ------ | ------------------------------------- | ----------------------------------------------------------- |
| `→`    | функциональная зависимость            | `X → Y` — «X определяет Y»                                  |
| `→→`   | многозначная зависимость (MVD)        | `A →→ B` — «одному A соответствует множество B»             |
| `*`    | зависимость проекции/соединения (PID) | `*(R₁, …, Rₙ)` — «R восстанавливается соединением проекций» |
| `⁺`    | замыкание атрибутов                   | `Z⁺` — множество всех атрибутов, выводимых из Z             |
| `π`    | проекция                              | `π_{A,B}(R)` — оставить только столбцы A, B                 |
| `⨝`    | естественное соединение               | соединяет две таблицы по общим атрибутам                    |
| `\`    | разность множеств                     | `R \ B` — все атрибуты R, кроме атрибутов B                 |
| `⊆`    | подмножество (нестрогое)              | `A ⊆ B` — «A входит в B, возможно совпадая»                 |
| `⊄`    | не подмножество                       | `A ⊄ B` — «A не входит в B целиком»                         |
| `∩`    | пересечение множеств                  |                                                             |
| `∪`    | объединение множеств                  |                                                             |
| `∈`    | принадлежит множеству                 | `A ∈ Z` — «A входит в Z»                                    |
| `⟺`    | эквивалентность                       | «тогда и только тогда»                                      |
| `∧`    | логическое И                          | «и то, и другое»                                            |
| `∨`    | логическое ИЛИ                        | «хотя бы одно из двух»                                      |
| `¬`    | логическое НЕ                         | «неверно, что»                                              |
| `≠`    | не равно                              |                                                             |

Строка для быстрого копирования:
`→` `→→` `*` `⁺` `π` `⨝` `\` `⊆` `⊄` `∩` `∪` `∈` `⟺` `∧` `∨` `¬` `≠`

### Задача 1. БИБЛИОТЕКА (2НФ)

Схема:
ВЫДАЧА*КНИГ(ЧИТ*БИЛЕТ, ИМЯ*ЧИТАТЕЛЯ, КНИГА*ШИФР, НАЗВАНИЕ, АВТОР,
ДАТА*ВЫДАЧИ, ДАТА*ВОЗВРАТА)

Правила предметной области:

- У каждого читателя один уникальный номер билета и одно имя.
- У каждой книги один уникальный шифр, одно название и один автор.
- Один и тот же читатель может взять одну и ту же книгу в разные даты — это разные выдачи.
- Ключ: `{ЧИТ_БИЛЕТ, КНИГА_ШИФР, ДАТА_ВЫДАЧИ}`.

Задание: привести к 3НФ.

> Вопрос: ключ состоит из трёх атрибутов. Если атрибут зависит только от одного из них — это нарушение 2НФ или 3НФ? Почему ответ не зависит от длины ключа?

### Задача 2. ЗАКАЗЫ (2НФ + 3НФ)

Схема:
ЗАКАЗЫ(НОМ*ЗАКАЗА, ДАТА, КЛИЕНТ, ГОРОД*КЛИЕНТА, СКИДКА*КЛИЕНТА,
ТОВАР, ЦЕНА*ТОВАРА, КОЛ_ВО)

Правила предметной области:

- У заказа один номер, одна дата и один клиент.
- У клиента один город и одна скидка.
- У товара одна цена.
- Один и тот же товар в разных заказах — разные строки.
- Ключ: `{НОМ_ЗАКАЗА, ТОВАР}`.

Задание: привести к 3НФ.

> Вопрос: сколько шагов декомпозиции потребуется? Почему после первого шага схема окажется в 2НФ, но ещё не в 3НФ?

### Задача 3. РАСПИСАНИЕ (перекрывающиеся ключи, НФБК)

Схема:
РАСПИСАНИЕ(ПРЕПОДАВАТЕЛЬ, ПРЕДМЕТ, АУДИТОРИЯ, ВРЕМЯ)

Правила предметной области:

- Один преподаватель ведёт один предмет (в этой модели).
- В одной аудитории в одно время — один предмет и один преподаватель.
- Один предмет в одно время ведёт один преподаватель в одной аудитории.

Задание:

1. Найдите все возможные ключи.
2. Определите нормальную форму.
3. Выполните декомпозицию до НФБК.
4. Проверьте, сохраняются ли при декомпозиции все исходные FD.

> Вопрос: что именно теряется при декомпозиции до НФБК и почему на практике в такой ситуации часто остаются в 3НФ?

### Задача 4. СЕМИНАРЫ (MVD, 4НФ)

Схема:
СЕМИНАР(ПРЕПОДАВАТЕЛЬ, КУРС, УЧЕБНИК)

Правила предметной области:

- Преподаватель может вести несколько курсов.
- Преподаватель может рекомендовать несколько учебников.
- Курсы и учебники независимы друг от друга : рекомендация учебника не привязана к конкретному курсу.

Задание: привести к 4НФ.

> Вопрос: почему здесь недостаточно обычной FD, и как понять, что в данных действительно есть MVD, а не просто «так совпало»?

### Задача 5. ПОСТАВКИ (PID, 5НФ)

Схема:
ПОСТАВКИ(ПОСТАВЩИК, ДЕТАЛЬ, ПРОЕКТ)

Правила предметной области:

- Поставщик может поставлять детали в проекты.
- Циклическое ограничение: если поставщик поставляет какую-то деталь и участвует в каком-то проекте, и эта деталь используется в этом проекте, то он поставляет эту деталь в этот проект.

Задание: привести к 5НФ.

> Вопрос: как отличить эту PID от случая, когда в отношении есть две независимые MVD? В чём принципиальная разница между 4НФ и 5НФ?

### Задача 6. ★ КИНОТЕАТР (комбинированная)

Схема:
СЕАНС(ФИЛЬМ, ЗАЛ, ДАТА, ВРЕМЯ, ЖАНР, РЕЖИССЁР, ВМЕСТИМОСТЬ_ЗАЛА, ЦЕНА)

Правила предметной области:

- У фильма один жанр и один режиссёр.
- У зала одна вместимость.
- В одном зале в одно время (в одну дату) — один фильм.
- Цена билета зависит только от зала и времени суток , но не зависит от даты (утренние сеансы всегда дешевле, вечерние дороже — независимо от дня).
- Ключ: `{ЗАЛ, ДАТА, ВРЕМЯ}`.

Задание: привести к 3НФ. Обратите особое внимание на FD, где детерминант — часть ключа, но не подмножество «первых N атрибутов».

> Вопрос: цена зависит от `{ЗАЛ, ВРЕМЯ}`, а ключ — `{ЗАЛ, ДАТА, ВРЕМЯ}`. Это нарушение 2НФ или 3НФ? Почему такая «неочевидная» частичная зависимость часто ускользает от внимания при проектировании?
