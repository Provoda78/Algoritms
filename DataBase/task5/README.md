# Семинар 5. Проектирование ER-модели — творческое задание

## Цель

Придумать свою предметную область, построить для неё ER-диаграмму,
получить реляционную схему и проверить, что она находится в 3НФ.

Это творческое задание — не разбор готовой схемы, а проектирование с нуля.
Примеры с лекций (библиотека, аэропорт, университет, расписание рейсов,
заказы, самолёты) использовать нельзя .

---

## Что нужно сделать

### Шаг 1. Придумать предметную область

Придумайте свою область — любую, в которой вы разбираетесь. Идеи:

- кулинарный сайт с рецептами;
- музыкальный сервис;
- фитнес-клуб;
- доставка еды;
- онлайн-курсы;
- железнодорожные перевозки;
- ферма, зоопарк, автосервис, кинотеатр — что угодно.

Главное — не берите примеры с лекций и не берите учебные классики
(«студент—курс—преподаватель», «заказчик—заказ—товар»).

### Шаг 2. Сформулировать правила области

Напишите 4–6 предложений текстом — как в лекции описывали библиотеку.
Пример:

> У каждого клиента фитнес-клуба есть ФИО и номер карты.
> Клуб предлагает разные тренировки; у каждой есть название, тренер и цена.
> Один клиент может ходить на много тренировок, и на одну тренировку
> записывается много клиентов. Каждая запись фиксирует дату посещения.

### Шаг 3. Выделить сущности и связи

Требования к модели:

- 3–4 сущности (не меньше трёх, не больше четырёх).
- Минимум одна связь 1:N .
- Минимум одна связь M:N (реализуется через промежуточную
  сущность, как в лекции ВЫДАЧА).
- Минимум одна обязательная связь (сплошная линия).
- Минимум одна необязательная связь (пунктирная линия).
- У каждой сущности должны быть свои атрибуты — минимум 2–3.

### Шаг 4. Построить ER-диаграмму

Используйте один из инструментов , разобранных в лекции:

| Инструмент   | Как использовать                            |
| ------------ | ------------------------------------------- |
| dbdiagram.io | описать схему на DSL, экспортировать PNG    |
| draw.io      | нарисовать вручную, экспортировать PNG/SVG  |
| PlantUML     | сгенерировать из текста, экспортировать PNG |

Нотация — как в лекции: цифры `1`, `N`, `M` на концах связей,
сплошные линии для обязательных, пунктирные — для слабых/необязательных.
Crow's foot («птичья лапка») не использовать.

Приложите картинку диаграммы (PNG или SVG).

### Шаг 5. Описать таблицы

По вашей ER-диаграмме получите реляционную схему. Оформите её как
список таблиц в одном из двух видов:

Вариант A — текстом (как в лекции):
АВТОР(код, ФИО)
КНИГА(ISBN, название, код*автора)
ВЫДАЧА(ISBN, номер*читателя, дата)

text

где подчёркнутый столбец — это PRIMARY KEY, а курсив — FOREIGN KEY.

Вариант B — таблицей с колонками «Столбец» и «Ключ»:

| Столбец    | Ключ |
| ---------- | ---- |
| ISBN       | PK   |
| код_автора | FK   |

### Шаг 6. Проверить 3НФ

Для каждой таблицы напишите 2–3 предложения:

- какой у неё первичный ключ;
- все ли неключевые атрибуты зависят только от ключа ;
- нет ли частичных зависимостей (от части составного ключа);
- нет ли транзитивных зависимостей (неключевой → неключевой).

Если нашли нарушение — исправьте схему и объясните, что было не так.
